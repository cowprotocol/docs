# x402 recovery and withdrawals

Start with the [x402 quickstart](./x402.mdx) to install the SDK and set up your payer.
This page contains the full runnable example, optional limits, recovery guidance and withdrawal steps.
Use the same project directory and preserve its saved files when moving between the examples.

## Complete quote example

The SDK handles the payment protocol. The extra code here configures your limits,
checks the RPC and receiver, saves signed attempts and original channel terms, and reports errors.
These are application safeguards, not additional protocol steps you must implement yourself.

### Inspect current terms

Save <a href="/code-examples/x402/inspect.mjs" download="inspect.mjs">inspect.mjs</a> and run `node inspect.mjs`.
It shows the current price, minimum deposit and withdrawal delay without a key, signature or payment.
Fund your wallet with enough Base USDC if you accept the terms.

### Client limits

The example defaults to **0.001 USDC per quote**, **1 USDC per deposit or top-up**, and a **24-hour maximum accepted withdrawal delay**. These are client limits, not guaranteed server terms. If an offer exceeds them, the script stops before signing.

<details>
<summary>Optional limits</summary>

```text
# Optional overrides; these are the example's defaults.
MAX_QUOTE_USDC=0.001
MAX_DEPOSIT_USDC=1
MAX_WITHDRAW_DELAY_HOURS=24
```

`MAX_WITHDRAW_DELAY_HOURS` only limits which offers your client accepts. It does not choose the waiting period: a new channel takes the delay advertised by the server, and keeps that delay for its lifetime. You can omit this setting; the example accepts delays up to 24 hours.

Enter price and deposit limits in human USDC units.
A per-deposit limit applies to each top-up; it is not a lifetime spending cap.

</details>

### Run the complete example

Save <a href="/code-examples/x402/quote.mts" download="quote.mts">quote.mts</a> in the project directory.
It checks payment terms, uses SDK receipt validation and saves channel state and recovery files.
The example uses `@x402/*` **2.26.0**.

```bash
node --env-file=.env --import tsx quote.mts
```

A successful run prints `status: 200`, `quoteReceived: true`, the charge, a saved channel-file path and the quote JSON.
The first request funds the channel; later requests reuse it and top up when needed, within your limits.
The CoW Protocol x402 payment service pays deposit and collection gas.

Run one request at a time per channel and keep the saved files across restarts.

## Recover an uncertain payment

The SDK handles a corrective `402` inside `wrapFetchWithPayment`: it validates the returned channel/voucher state, updates local storage and retries once with a fresh payment. This can produce a new charged quote; it does not retrieve a lost quote response.
If the script still fails or the connection drops, follow these steps before rerunning it or withdrawing.

**1. Stop requests on this channel and keep the evidence.** Preserve `x402-state/`, `x402-channels/`, all `x402-attempts/` files from the run, the error output and any transaction hash. Use the `savedAttempt` path printed by the error in step 2. Do not delete state, manually lower its charged total or replay the signed attempt to check its status.

**2. Inspect the saved attempt and local state.** Run this from the same project directory, replacing the attempt filename. It reads local files without signing or sending a request:

```bash
ATTEMPT=./x402-attempts/YOUR_ATTEMPT.json node --input-type=module <<'JS'
import { readFileSync } from "node:fs";
import { getChannel } from "@x402/evm/batch-settlement/client";
import { FileClientChannelStorage } from "@x402/evm/batch-settlement/client/file-storage";

const attempt = JSON.parse(readFileSync(process.env.ATTEMPT, "utf8"));
const channelId = attempt.payload.voucher.channelId;
const storage = new FileClientChannelStorage({ directory: "./x402-state" });
const local = await getChannel(storage, channelId);
console.log({
  channelId,
  paymentNetwork: attempt.accepted.network,
  paymentType: attempt.payload.type,
  signedLimitAtomic: attempt.payload.voucher.maxClaimableAmount,
  recordedChargesAtomic: local?.chargedCumulativeAmount ?? null,
});
JS
```

The signed limit is a cumulative authorization cap, not proof of a charge. `recordedChargesAtomic` is the client's last recorded total; it may be stale after a lost response. A missing record does not mean the payment failed. Keep the signed attempt private.

**3. Check the chain without changing it.** Save <a href="/code-examples/x402/withdraw.mts" download="withdraw.mts">withdraw.mts</a>. Set `CHANNEL=./x402-channels/YOUR_CHANNEL_ID.json` in `.env` using the channel ID above, and keep `RPC_URL` on the payment chain. Then run:

```bash
node --env-file=.env --import tsx withdraw.mts status
```

This reads the channel balance, claimed total and withdrawal status; it sends no transaction and needs no private key. If the original error included a transaction hash, also check its receipt in the payment chain's explorer. A pending or missing receipt remains unresolved. A successful deposit proves that funds reached the channel, not that the quote was charged. The on-chain claimed total omits charges awaiting collection.

**4. Establish the payment outcome.** A completed example run prints `status: 200`, `quoteReceived: true` and `chargedUSDC` from the payment receipt. If you have that output, that request succeeded and another run is a new purchase. If the receipt was lost, failed validation, or the script reported an accounting/settlement error, the checks above cannot establish whether that request was charged.

Contact [CoW Protocol Discord](https://discord.com/invite/cowprotocol) with the payment network, channel ID, approximate request time, error code and any transaction hash. Ask the team to confirm the request's charge and reconcile the channel state before another payment or withdrawal. Do not post your private key, signed attempt or full state files. There is no public read-only payment-status endpoint for this check.

**5. Resume only after the uncertainty is resolved.** Keep using the reconciled state and original channel configuration. Each successful new quote can incur another charge. If you are finished with the channel, follow the withdrawal steps below.

:::warning Do not reset state from on-chain claims

SDK 2.26.0's `recoverChannel()` rebuilds the charged total from on-chain claims. It is not a general repair for a lost response while uncollected charges may exist. The normal corrective-`402` path uses `processCorrectivePaymentRequired()` through the SDK hooks; do not bypass those checks or manually edit the charged total.

:::

## Withdraw unused funds

You initiate a withdrawal, wait for the saved channel's deadline, then finalize it.
These are **two transactions**, paid by your wallet in Base ETH for this example.
Finalization returns tokens to the payer; it is not automatic.

Save <a href="/code-examples/x402/withdraw.mts" download="withdraw.mts">withdraw.mts</a> in the same project directory.
In `.env`, set `CHANNEL` to the channel-file path printed by the quote example.
Keep `RPC_URL` on that channel's payment chain.

```text
CHANNEL=./x402-channels/YOUR_CHANNEL_ID.json
```

**1. Check status** without spending gas:

```bash
node --env-file=.env --import tsx withdraw.mts status
```

**2. Stop using the channel and initiate** the withdrawal:

```bash
node --env-file=.env --import tsx withdraw.mts initiate
node --env-file=.env --import tsx withdraw.mts status
```

**3. Wait until `finalizeAt`**, calculated from the on-chain initiation time and that channel's original delay.
A new offer cannot change it.

**4. Finalize**, then check the receipt and your token balance:

```bash
node --env-file=.env --import tsx withdraw.mts finalize
node --env-file=.env --import tsx withdraw.mts status
```

The x402 payment service may collect outstanding charges during the wait, reducing the returned amount.
Collection happens only when economic; uncollected fees do not extend the withdrawal deadline.
A pending withdrawal cannot be cancelled.
If a transaction times out, check its hash and status before sending another.
Resolve uncertain payments before withdrawing.

## Other payment options and help

The current options are USDC or \$COW on Base, USDC on Ethereum and USDC on BNB.
\$COW and BNB USDC require an explicit SDK asset entry and Permit2 approval.
Approval and withdrawal gas is paid in the payment chain's native token.
\$COW amounts have no guaranteed dollar equivalent.

Use the [live API reference](https://x402.cow.fi/docs/) for payment fields, networks and errors,
or download the [OpenAPI specification](https://x402.cow.fi/openapi.json).
Contact [CoW Protocol Discord](https://discord.com/invite/cowprotocol) with your network, channel ID and transaction hash;
never share keys or signed payments.
